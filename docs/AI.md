# Medhmar AI assistant

The assistant explains Medhmar workflows in Arabic and English. It uses a
version-controlled platform guide and, when IDs are supplied, selected public
fields from one race and/or one active camel. It is read-only and stateless.

## Run in IntelliJ

1. Reload Maven after pulling the branch. Use the project's JDK 21.
2. Open **Run > Edit Configurations > GulfRacingApplication**.
3. Keep the existing `DB_URL`, `DB_USERNAME` and `DB_PASSWORD` variables.
4. Add these environment variables, entering your own API key privately:

   ```text
   SPRING_PROFILES_ACTIVE=ai
   AI_API_KEY=<your API key>
   AI_MODEL=gpt-4o-mini
   ```

   If Google login or SMTP is already enabled, combine profiles, for example
   `SPRING_PROFILES_ACTIVE=ai,google,mail`.
5. Run the application, sign in, and call `GET /api/ai/status` using the session.
6. Send a chat request with a fresh CSRF token as described below.

Spring Boot does not automatically read `.env` files. `.env.example` documents
the names only. Do not commit a key or send it through the frontend.
The default model is configurable. The profile uses a non-reasoning chat model
with `temperature` and `max-tokens`; if choosing a reasoning model, also adjust
its supported options (for example `max-completion-tokens` instead of
`max-tokens`, and omit unsupported temperature settings).

Without the `ai` profile, the rest of the backend starts without AI credentials.
Chat returns 503. With the profile enabled, a valid model account/key is required
for real answers. Availability means a model is configured, not that a live
provider health check was performed.

## API contract

`POST /api/ai/chat` requires an active session and CSRF header.

```json
{
  "question": "كيف أسجل هجن في السباق؟",
  "language": "ar"
}
```

To ask about a specific record, optionally include `raceId` and/or `camelId` with
real IDs from the corresponding public API. Do not pass invented IDs. English
uses `"language": "en"`; omitted language defaults to Arabic.
Question length is 1–2000 characters (nonblank). IDs must be positive.

Illustrative response (wording is model-generated):

```json
{
  "answer": "يمكن للمالك تسجيل جمل نشط في سباق مفتوح قبل موعد بدايته. [platform-guide]",
  "language": "ar",
  "sources": [
    {"id": "platform-guide", "label": "Medhmar platform guide", "path": "/api/ai/guide"}
  ]
}
```

`sources` is assembled by the server from the actual context, not generated by
the model. It identifies the material supplied; it does not prove every sentence
is correct. `GET /api/ai/guide` returns the maintained guide. Selected records
add source paths to their existing public APIs.

## Frontend integration example

Use this after login. Existing login rotates the CSRF token, so fetch a fresh
token before the chat request. The frontend's origin must be in the existing
`FRONTEND_ORIGINS` allowlist.

```javascript
const API = 'http://localhost:8080';

async function askAssistant(question, language = 'ar', context = {}) {
  const tokenResponse = await fetch(`${API}/api/auth/csrf`, {
    credentials: 'include'
  });
  if (!tokenResponse.ok) throw new Error('Could not get a CSRF token.');
  const csrf = await tokenResponse.json();

  const response = await fetch(`${API}/api/ai/chat`, {
    method: 'POST',
    credentials: 'include',
    headers: {
      'Content-Type': 'application/json',
      [csrf.headerName]: csrf.token
    },
    body: JSON.stringify({
      question, language,
      raceId: context.raceId,
      camelId: context.camelId
    })
  });
  const data = await response.json();
  if (!response.ok) throw new Error(data.message ?? 'The assistant is unavailable.');
  return data;
}

// Display the answer as plain text, never as unsanitized HTML.
// answerElement.textContent = (await askAssistant('كيف أسجل في السباق؟')).answer;
```

## Rules and data boundary

- `ai/assistant-policy.txt` defines the assistant's scope, language, uncertainty
  and instruction-handling behavior.
- `ai/platform-guide.txt` is the reviewed knowledge source. Maintain it as
  platform rules evolve. It is not populated from arbitrary uploaded documents.
- The caller cannot supply system prompts, tools, model names, arbitrary URLs,
  SQL or conversation IDs through this API. Question text is sent as a user message.
- Database context is explicitly projected into bounded public fields. No JPA
  entity, account email, credential, ownership relation, private offer, agreement
  or training log is serialized to the model. Record names are untrusted data.
- The user's question and selected public context go to the configured model
  provider. Tell users not to include secrets or private information in questions.
- No chat history is stored, and the application does not log prompts or answers.
  The OpenAI chat request sets `store=false`; provider retention rules still apply.
- No AI write tools are installed. Authorization and data selection are enforced
  in Java; wording and topic restrictions are model instructions, not a security
  boundary or a guarantee against hallucination/prompt injection.
- With no record IDs the assistant only has the guide. It cannot list upcoming
  races, infer race results or perform a live catalogue search from question text.

## Limits and errors

| Setting / status | Behavior |
| --- | --- |
| AI_REQUESTS_PER_MINUTE (10) | Per authenticated user, per process; 60-second windows |
| AI_MAX_CONCURRENT_REQUESTS (4) | Maximum simultaneous assistant requests per process |
| AI_MAX_TOKENS (600) | Model completion limit for the default non-reasoning model |
| Provider timeout | 20 seconds; SDK retries disabled; Spring retry attempts set to one |
| 400 | Blank/oversized question, unsupported language or invalid ID |
| 401 / 403 | Missing/invalid account session or CSRF/access restriction |
| 404 | Selected record missing or camel inactive |
| 429 AI_RATE_LIMITED | Per-account quota exhausted or global concurrency limit reached |
| 502 AI_PROVIDER_UNAVAILABLE | Provider failure, empty answer or invalid oversized answer |
| 503 AI_NOT_CONFIGURED | Assistant disabled or no model configured |

The limiter uses a bounded in-process cache. For multiple instances, enforce a
shared quota at a trusted gateway or shared backing store. `status.available`
does not consume model quota. Requests are independent; no streaming is exposed.

## Tests

```sh
cd backend
mvn clean verify
```

Integration tests cover authorization/CSRF, account suspension, validation,
public-only context, language selection, source construction, missing/inactive
records, default-disabled startup, quota enforcement and sanitized failures.
Limiter tests cover per-account isolation, window reset and concurrent capacity.
`AiProviderIntegrationTests` runs the real Spring AI/OpenAI adapter against a
local HTTP stub and checks model options, typed messages, response parsing and
single-attempt failures. It requires no real credentials or external model calls.
These tests validate the integration, not the semantic quality of live answers.

Before enabling for users, test Arabic/English questions, unsupported facts,
unrelated prompts and instruction attacks against the chosen live model.

## Implementation files

- `controller/AiController.java`: session-protected REST endpoints.
- `dto/AiDtos.java`: input constraints and response contracts.
- `ai/AiAssistantService.java`: orchestration and safe provider errors.
- `ai/AiKnowledgeService.java`: guide and explicit public projections.
- `ai/SpringAiModelGateway.java`: Spring AI model invocation.
- `ai/AiRequestLimiter.java`: user quotas and global concurrency bound.
- `application-ai.properties`: opt-in provider configuration.

Java paths are relative to `backend/src/main/java/com/gulfracing/`; resources
are under `backend/src/main/resources/`.

Provider configuration reference: [Spring AI OpenAI Chat](https://docs.spring.io/spring-ai/reference/api/chat/openai-chat.html).
